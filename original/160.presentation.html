섹션 1 · 핵심 비교

핵심 차이 = 스킬 상속 방식

CLAUDE.md MCP 도구 스킬 대화 기록
팀원 ✓ 자동 ✓ 자동 ✓ 전부 자동 ✗ 프롬프트만
서브에이전트 ✓ 자동 ✓ 자동 ⚠ 선택 지정 ✗ 프롬프트만
💡

유일한 차이는 스킬입니다.
팀원은 프로젝트의 모든 스킬을 전부 자동으로 가져가고, 서브에이전트는 골라서 넣어줘야 합니다.

🎯

설계 기준:
스킬을 정밀하게 제어해야 한다면 → 서브에이전트
모든 팀원이 같은 스킬 세트면 → 팀원이 편리

섹션 2 · 승인 기준

프롬프트로 자동 판단 기준 설정

리드가 알아서 판단하도록 기준을 미리 정해두세요.

🧪
"테스트 커버리지를 포함하는 계획만 승인해."
→ 테스트 없는 계획은 자동 거절
🛡️
"데이터베이스 스키마를 수정하는 계획은 거절해."
→ DB 변경은 무조건 차단
⚡
"성능 영향 분석이 포함된 계획만 승인해."
→ 성능 고려 없으면 거절
💡

혼자 쓸 때든 팀으로 쓸 때든, "계획 먼저" 원칙은 변하지 않습니다. 이 습관 하나만 들여도 토큰 낭비가 확 줄어들어요.

섹션 3 · 비용 절감

4가지 비용 절감 전략

01
팀이 진짜 필요한지 판단
소통 불필요한 작업은 서브에이전트 사용. 조율 오버헤드 제거.
02
최소 인원으로 시작
3~5명이면 충분. 10명은 수확 체감이 심함.
03
끝난 팀원은 즉시 종료
세션이 살아있으면 계속 토큰 소모. 바로 종료 요청.
04
CLAUDE.md에 비용 지침
broadcast 금지, 완료 후 즉시 종료, 반복 3회 제한.
섹션 3 · 선택 기준

서브에이전트 vs 에이전트 팀

이 4가지 질문만 던져보면 바로 답이 나옵니다.

팀원 간 소통이 필요한가?
Yes → 에이전트 팀
No → 서브에이전트
프로젝트 컨텍스트 전체 필요한가?
Yes → 에이전트 팀
No → 서브에이전트
독립적 병렬 작업인가?
Yes → 서브에이전트로 충분
크로스 레이어 협업이 필요한가?
Yes → 에이전트 팀
섹션 4 · Hooks

Hooks = 이벤트 기반 자동화

"어떤 일이 일어나면, 이 스크립트를 자동으로 실행해라"

📡
이벤트 발생
팀원이 작업 완료
또는 idle 상태
→
⚙️
셸 스크립트 실행
테스트, lint,
타입 체크 등
→
🚦
결과에 따라 제어
exit 0 = 통과
exit 2 = 차단
💡

exit code는 스크립트가 끝날 때 보내는 신호 번호. 0 = "OK, 통과!", 2 = "문제 있어!" — 이 신호에 따라 Claude Code가 다음 동작을 결정합니다.

섹션 4 · 훅 비교

TeammateIdle vs TaskCompleted

TeammateIdle
팀원이 할 일을 끝내고 쉬고 있을 때 발동
exit 2 → 피드백을 전달해서
팀원이 계속 작업하도록
"쉬고 있는 직원에게 추가 업무를 주는 것"
# 활용 예시
"작업 끝나면 요약 보고서를 작성해라"
TaskCompleted
팀원이 태스크를 "완료" 처리할 때 발동
exit 2 → 완료 자체를 차단하고
피드백 전달
"팀장이 결과물 검토 후 돌려보내는 것"
# 자동 테스트 게이트
npm test || exit 2
핵심 정리

오늘 배운 4가지

01
컨텍스트 계승
팀원은 새 세션으로 생성 — CLAUDE.md, MCP, 스킬 전부 자동. 서브에이전트는 스킬만 선택 주입.
02
Plan Approval
구현 전에 계획 승인 → 잘못된 방향으로 토큰 낭비 방지.
03
모델 믹싱
리드 = Opus, 팀원 = Sonnet → 비용 대폭 절감.
04
Hooks
TaskCompleted 훅으로 자동 품질 게이트 → 테스트 안 돌리면 완료 불가.
🚀

이 4가지만 적용해도 에이전트 팀을 훨씬 효율적으로 쓸 수 있습니다.
