## 핵심 스펙

- Claude Code 컨텍스트 윈도우: **1,000,000 토큰 (1M)**
- `/usage` 슬래시 커맨드 출시

## 핵심 개념

### 컨텍스트 로트 (Context Rot)
- 컨텍스트가 커질수록 모델 성능이 저하되는 현상
- 원인 1: 주의력이 더 많은 토큰으로 분산
- 원인 2: 오래된 관련 없는 내용이 산만함을 야기
- 결론: 1M이 크다고 무조건 좋은 게 아니다 — 관리해야 좋다

### 자동 컴팩션
- 컨텍스트 윈도우 끝에 도달하면 자동으로 요약되어 새 윈도우로 계속
- 문제: 모델이 가장 혼란스러울 때(컨텍스트 로트 상태) 요약이 발생

## 매 턴마다의 5가지 분기점

1. **Continue** — 같은 세션에서 다른 메시지 전송
2. **/rewind (Esc Esc)** — 이전 메시지로 점프하여 그곳에서 다시 시도
3. **/clear** — 새 세션 시작 (보통 학습한 내용의 간단한 설명과 함께)
4. **/compact** — 세션 요약 후 요약 위에서 계속
5. **Subagents** — 다음 작업을 자체 깨끗한 컨텍스트를 가진 에이전트에 위임, 결과만 반환

## 세부 지침

### 새 세션 시작 시기
- 일반 규칙: "새 작업을 시작할 때는 새 세션도 시작해야 함"
- 1M 컨텍스트로 더 긴 작업 가능하지만 컨텍스트 로트 발생할 수 있음
- 예외: 관련 작업에서 일부 컨텍스트가 필요할 때 (예: 방금 구현한 기능의 문서 작성)

### 수정 대신 리와인드 활용
- 더블 Esc 또는 `/rewind` — 이전 메시지로 점프, 이후 메시지 삭제
- 나쁜 접근: "approach A 말고 B로 가줘"를 수정 메시지로 추가 → 실패한 시도가 컨텍스트에 남음
- 좋은 접근: `/rewind` 후 "approach A를 사용하지 마세요, foo 모듈이 그것을 노출하지 않습니다—B로 직접 가세요"로 재프롬프트
- "summarize from here" 로 Claude가 학습사항을 요약하고 미래의 자신으로부터의 메시지 생성

### 컴팩션 vs. 새 세션
**Compact (`/compact`)**
- 모델에 지금까지 대화 요약 요청, 이력을 요약으로 대체
- 손실 있지만 직접 쓸 필요 없음 — 노력↓
- 지시사항으로 조정 가능: `/compact focus on the auth refactor, drop the test debugging`

**/clear**
- 사용자가 직접 작성: "우리는 인증 미들웨어를 리팩토링하고 있음, 제약은 X, 중요 파일 A와 B, 접근법 Y 배제"
- 더 많은 작업이지만 관련성은 사용자가 결정 — 제어↑

### 나쁜 자동컴팩트 원인
- 모델이 작업 방향을 예측 못 할 때 발생
- 예: 긴 디버깅 후 자동컴팩트 → 다음 메시지가 "이제 bar.ts의 다른 경고 수정" → 디버깅 중심으로 요약되어 경고 내용 삭제
- 문제: 컨텍스트 로트로 모델이 컴팩팅할 때 가장 약한 상태
- 해결: 1M 컨텍스트로 수행할 작업 설명과 함께 미리 `/compact` 실행

### Subagents 활용 시점
- 중간 산출물이 많이 생성되지만 다시는 필요 없을 작업
- 멘탈 테스트: *이 도구 산출물을 다시 필요로 할까, 아니면 결론만?*
- 사용 예:
  - 사양 파일 기반 작업 결과 검증
  - 다른 코드베이스의 인증 흐름 요약
  - git 변경 기반 기능 문서 작성

## 상황별 선택 매트릭스

| 상황 | 권장 | 이유 |
|------|------|------|
| 같은 작업, 컨텍스트 여전히 관련 | Continue | 모두 여전히 중요 |
| Claude가 잘못된 경로 진행 | /rewind | 유용한 파일 읽기 유지, 실패 제거 |
| 세션이 디버깅으로 부풀려짐 | /compact | Claude가 중요한 것 결정 |
| 새로운 작업 시작 | /clear | 로트 없음; 사용자 제어 |
| 많은 산출물 생성 단계 | Subagent | 중간 노이즈는 자식에, 결과만 반환 |
